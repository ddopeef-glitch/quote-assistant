# 架构取舍

## 语义提案与交易事实分开

模型输出商品候选、规格、箱数、等级及原始证据引用。价格、包装和重量仍从本地 Excel 主数据读取。模型不具备写主数据、确认交易或调用输出函数的工具。

目录通过 `query_batch` 按需检索。每个来源先按分类证据收窄范围，后续查询和分页不能突破该范围。无分类证据时按演示合同默认玛钢；明确的沟槽、球铁等证据保留。候选 ID 是目录标识，不是模型可以自行发明的事实。

程序检查 JSON 字段、重复键、非有限数值、证据引用、输入单元覆盖、候选归属及已选候选的一致性。通过这些检查只表示提案具备可核对结构，不能证明业务语义正确，因此仍有五列人工确认。

## 为什么保留失败占位

一个来源请求耗尽或网络失败时，其他来源可能已经有结果。失败来源保留原始内容与可见待处理行，避免“只导出成功部分”造成无提示漏项。模型鉴权、主数据变更、审计写入失败等全局错误会停止后续来源。

失败占位不能靠随便补齐五列变成有效提案；用户需重新识别，或明确删除该占位并核对遗漏内容。

## 为什么预览和最终输出复用渲染器

预览在内存中生成，不保存客户名称或创建报价记录。最终输出重新核验确认字段和主数据指纹，使用同一渲染器排版。PDF 与每页 PNG 排他创建并回读后，才生成本地报价记录并记住客户名称；任何步骤失败都回滚本次新文件。

指纹比较基于文件内容，不只看修改时间。已确认字段改变或主表更新，旧单价和预览不能继续使用。

## 离线演示的真实性边界

`src/demo.py` 为固定三行合成询价提供两轮预设响应。第一轮提出目录查询，第二轮用实际本地返回的 ID 构造预设提案。它复用生产路径中的校验、人工确认与报价核心，但没有进行模型推理，不能评估识别准确率。

所有主数据由 `scripts/create_demo_data.py` 从明确的合成常量构建，不读取或改写真实企业工作簿。缺面价、缺包装、大小写档位和多目标别名都作为可测试的例子保留。

## 保留的复杂性与限制

现有规则解析器服务于旧的独立提取接口及相关测试；正式 AI 入口保留完整原文，不先用规则筛掉未知商品。此版保留相关代码以维持调用兼容，没有再做一次与公开准备无关的大规模拆分。

OCR 使用进程内锁，客户名称历史也是进程内保护。代码目前适用于本地单进程使用；多实例部署需要另行设计共享存储、任务队列、权限隔离与事务边界。

真实 API 路径每来源最多两轮；在最后一轮仍需查询的复杂请求可能未完成。当前保留请求审计和失败状态，不把未完成提案伪装成成功。
